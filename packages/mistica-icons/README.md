# @telefonica/mistica-icons

The icons of the Mística design system, as React components.

This package holds one module for each icon. It has no entry point on purpose, so an application loads the
icons that it uses and nothing more, especially when it comes to using federated modules.

## Install

```bash
yarn add @telefonica/mistica @telefonica/mistica-icons
```

`@telefonica/mistica` is a peer dependency. The icons read the theme of that package at run time, so an icon
always needs a `<ThemeContextProvider>` above it.

## Usage

```tsx
import IconStarRegular from '@telefonica/mistica-icons/icon-star-regular';

<IconStarRegular size={24} color={skinVars.colors.brand} />;
```

There is no barrel, so `import {IconStarRegular} from '@telefonica/mistica-icons'` does not work. Each icon
has its own path, in kebab case.

### If you want one import line

Write the barrel in your own application, and re-export the icons that you use:

```tsx
// src/icons.ts
export {default as IconStarRegular} from '@telefonica/mistica-icons/icon-star-regular';
export {default as IconSearchRegular} from '@telefonica/mistica-icons/icon-search-regular';
```

```tsx
import {IconSearchRegular, IconStarRegular} from './icons';
```

Your bundler shakes that file, so the bundle holds the icons that you render. The same barrel inside this
package would not be safe: a `shared` module keeps every export, and that is the defect that this package
removes. [codemods/mistica-icons-codemod.js](../../codemods/mistica-icons-codemod.js) writes the deep imports
of an existing codebase for you.

The icon metadata lives in a second entry point:

```tsx
import {iconKeywords, iconCategories} from '@telefonica/mistica-icons/keywords';
```

## Module Federation

This package exists because a `shared` module keeps every export, so a barrel of 2225 icons reaches the bundle
of the host.

Leave this package out of the `shared` list. Each application then bundles the icons that it uses, and an icon
holds no state, so a second copy is safe. A measurement of the alternative, a shared path prefix, sits in
[examples/module-federation](../../examples/module-federation/README.md): it emits 127 files instead of 24.

```js
shared: {
    react: {singleton: true},
    'react-dom': {singleton: true},
    '@telefonica/mistica': {singleton: true},
}
```

`shared: {'@telefonica/mistica-icons': {}}` fails, because the package has no entry point to provide.

See [doc/module-federation.md](../../doc/module-federation.md) for the complete guide.

## Versions and changelog

This package follows the version of `@telefonica/mistica`, and both packages come from the same release.
[CHANGELOG.md](./CHANGELOG.md) holds the icon changes only, so a version with no entry carries no icon change.

One release computes one version number for the two packages. A breaking change in either package therefore
raises the major of both. So a major of this package can arrive with no entry in its changelog, and the
breaking note then sits in the [changelog of `@telefonica/mistica`](../../CHANGELOG.md). Install the two
packages with the same version: the manifests declare each other with a `^` range, and a mixed pair breaks the
theme.

## Contributing

The sources in `src/generated` are autogenerated. Do not edit them by hand. To import new artwork from the
[mistica-icons](https://github.com/Telefonica/mistica-icons) repository, run `yarn import-mistica-icons` in
the root of this repository.

### The cycle between the two packages

An icon imports `@telefonica/mistica`, and 30 components of `@telefonica/mistica` import 52 icons from here.
The two manifests therefore form a cycle, and so does the module graph. Yarn, npm, webpack and Vite all accept
it, and it is safe: an icon reads the theme inside its render, never while its module evaluates.

`yarn circular-dependencies` excludes this package for that reason. The check still guards every cycle inside
`src/`, which is what it exists for. A `@telefonica/mistica-core` package would remove the cycle for good, and
that is the follow-up of issue [#1643](https://github.com/Telefonica/mistica-web/issues/1643).
